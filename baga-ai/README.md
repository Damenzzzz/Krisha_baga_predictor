# baga-ai — поиск, модель цены, агент и все интерфейсы

Это техническая часть нашего проекта: всё, что происходит после того, как парсер собрал
объявления. Обзор продукта, скриншоты и соответствие заданию — в [главном README](../README.md),
архитектура и путь запроса — в [ARCHITECTURE.md](ARCHITECTURE.md), все измерения — в
[EVALS.md](EVALS.md).

Авторы: Исламбек Султанбек и Нурдаулет.

![главная](docs/screenshots/home_hero.png)

## Запуск

```bash
cp .env.example .env          # GEMINI_API_KEY, ALEM_*, LANGFUSE_*; без ключей работают поиск и вердикт
docker compose up -d          # Qdrant + загрузка индекса + сайт → http://localhost:8501
```

Без Docker, Python 3.12:

```bash
pip install -r requirements.txt
python qdrant_store.py ensure           # векторы фото и описаний в Qdrant (один раз)
uvicorn server:app --port 8501          # сайт
python telegram_bot.py                  # бот (TELEGRAM_BOT_TOKEN от @BotFather)
python mcp_server.py --selftest         # MCP-сервер: клиент в памяти вызывает все инструменты
python auth.py add admin --role admin   # первый админ (или BAGA_ADMIN_USER / BAGA_ADMIN_PASSWORD)
pytest tests                            # 50 тестов, то же, что в CI
```

Эмбеддинги фото лежат в репозитории двумя частями (`artifacts/photo_emb.part*.npy`, лимит
GitHub — 100 МБ на файл) и склеиваются при первом запуске. Пересчитать их можно из фото:
`python run_pipeline.py embed` (≈ 45 минут на Apple M-серии).

Контактов в данных нет: мы проверили все 7 476 описаний — ни одного телефона.

## Как мы ищем

Запрос делится на две части: условия (комнаты, цена, район) — это фильтры, а «светлая кухня
с белыми фасадами» — это то, что нужно увидеть. «До 400 тысяч» эмбеддингом не выразить,
«скандинавский стиль» — фильтром тоже.

- **Фото — SigLIP 2** (`google/siglip2-base-patch16-224`): текст и картинки в одном
  пространстве, понимает русский. У DINOv3 нет текстового энкодера, open_clip ViT-B-32 слабо
  понимает русские запросы. Старшая версия SigLIP в 4–5 раз медленнее, а базовая нас
  устроила по качеству.
- **Тип комнаты — zero-shot той же моделью.** Кухня ищется среди кухонь, спальня — среди
  спален. Заодно отсекаются рендеры застройщиков и фасады.
- **Описания — ALEM text-1024.** SigLIP плохо сравнивает текст с текстом.
- **Слияние — RRF с весом описаний 0.5.** Косинусы двух моделей несравнимы по шкале, ранги
  сравнимы. Вес подобран визуальным судьёй: при равных весах нужное было видно на фото лишь
  в 59.5% топ-5, при 0.5 — в 81.9%.
- **Хранилище — Qdrant.** Фильтры по характеристикам выполняются внутри базы вместе с
  векторным поиском, а группировка по объявлению — одним запросом (у квартиры 10–20 фото,
  без группировки одна заняла бы весь топ). Два режима: встроенный, без сервера, и сервер
  из docker-compose.
- **Chunking не делаем.** Единица поиска — объявление, описание короче окна модели.
- **Препроцессинг** мы перенесли из прошлого соревнования на Kaggle («Lost in the Museum»):
  вписывание в квадрат с полями, чтобы кухня 4:3 не сплющивалась, и усреднение видов
  `l2 → mean → l2`. Мультимасштаб не перенесли: SigLIP обучена на фиксированном разрешении.

## Как мы оцениваем цену

Квантильная регрессия CatBoost (10/50/90 процентиль) на `log(цены)` и конформная калибровка.
Пользователю нужен коридор «похожие сдают за 380–470 тысяч», а не одно фальшиво точное
число. Логарифм — из-за длинного хвоста дорогих квартир.

Out-of-fold, 5 фолдов, страты по районам, группы по дублям — дубли одной квартиры не
попадают одновременно в обучение и проверку:

| Вариант | MAE, ₸ | Ошибка (MAPE) | Покрытие 10–90 | Ширина коридора |
|---|---|---|---|---|
| правило: медиана ₸/м² по району × комнатам × площадь | 107 952 | 22.3% | 79.3% | 69% |
| CatBoost, базовые признаки | 86 898 | 17.0% | 66.3% | 38% |
| + состояние ремонта | 85 674 | 16.6% | 66.5% | 38% |
| + признаки из описания (мебель, техника, депозит, санузел) | 85 066 | 16.4% | 65.2% | 36% |
| **+ конформная калибровка** | **85 066** | **16.4%** | **81.1%** | **52%** |

Голая квантильная регрессия давала покрытие 66% вместо 80%: коридор был слишком узким, и
каждая третья нормальная квартира получала бы «дороже похожих». Это мы починили
калибровкой, а не переобучением. По сегментам: Алматы — 16.1% и покрытие 81%, Каскелен —
22.7% и 79%, дорогие квартиры — 21.8% и 74%.

**Утечка, которую пришлось закрыть.** У 60% объявлений цена написана в описании, у 57.6% —
ровно целевое значение. `features.clean_description` маскирует любое число от 10 000, а
`assert_no_price_leak` роняет обучение, если цена всё же осталась в тексте.

Для объявлений из базы мы отдаём out-of-fold оценку — её строила модель, которая это
объявление не видела. Для новых квартир — модель, обученная на всех данных.

## Дубли объявлений

Одна квартира часто висит на krisha несколько раз — от разных агентов, с теми же фото и
разной ценой. Это забивает выдачу повторами и заставляет модель цены учиться на одной
квартире несколько раз.

1. **DINOv3 ViT-L** считает эмбеддинг каждого фото: здесь нужно найти **тот же самый** кадр,
   а не похожий по смыслу, и в этом DINOv3 сильнее SigLIP.
2. Косинус с заниженным порогом 0.88 даёт кандидатов.
3. **SIFT + RANSAC** проверяет каждого кандидата геометрически: настоящий дубль даёт сотни
   совпавших точек, похожая по стилю кухня — единицы.

| Порог по совпавшим точкам | Объявлений в группах | Самая большая группа |
|---|---|---|
| 18 | 1 171 | **210** — цепочка, а не дубли |
| **40** | **611** | **6** |
| 200 | 510 | 6 |

При слабом пороге квартиры с типовым ремонтом от застройщика сцепляются в одну гигантскую
группу. От 40 до 200 результат почти не меняется — значит, настоящие дубли лежат сильно выше
отсечки. Мы взяли 40 и добавили защиту: если группа выросла больше 20 объявлений, сборка
падает с ошибкой. В карточке это видно как «то же объявление встречается N раз».

## Ограничения

1. Модель знает цены **объявлений**, а не сделок: системное завышение рынка ей не видно.
2. Один срез данных — динамики рынка и мониторинга дрейфа пока нет.
3. Года постройки и типа дома в данных практически нет — из модели выпадает важный фактор.
4. Геозапросов нет: координаты есть только у 41% объявлений.
5. Классификатор комнат ошибается, и жёсткий фильтр по комнате иногда теряет правильный ответ.
6. Каскелен — 3.5% данных, там ошибка оценки выше.
7. Данные собраны для учебного некоммерческого проекта. В репозитории лежат обезличенные
   характеристики объявлений и векторы фото; сами фотографии не публикуются.
